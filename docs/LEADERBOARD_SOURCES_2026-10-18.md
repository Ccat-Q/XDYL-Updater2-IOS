# 排行榜数据来源切换

## 需求与实现

在现有喵币排行、在线排行中由用户选择数据来源，不替换原始榜单，也不自动切换。顶部原生分段选择器提供“原始榜单 / 个人主页”；默认原始榜单，主页模式显示余额或累计游玩，并支持查看玩家主页和下拉刷新。

原始榜单仅请求当前榜单路由，保持后端 `rank`，包括并列名次。主页模式合并两榜当前名单、去重后串行读取公开主页，再按对应数值排序。没有完整玩家目录或主页聚合排名接口的证据，因此明确标为“当前名单，非全服排名”。若要覆盖全服，需要后端新增完整名单或直接排序接口，不能由客户端假冒完整排名。

主页余额允许小数，数值排序不使用字符串大小；相同值采用 1/1/3 式名次。缺失、非法、明确未注册的余额，以及负时长不参与排名；真实 0 值参与。主页读取失败保留可识别的玩家行和失败提示，不使用原始榜单数值充当主页值。

## 影响范围

- 新增 `Core/Leaderboards.swift`：榜单模型、数值排序、身份去重、加载状态和旧请求失效保护。
- 新增 `UI/LeaderboardView.swift`：双来源选择、进度/错误、排名、主页导航。
- `ServicesView` 的两个榜单改为专用页面，其他服务及决斗榜不变。
- `APIClient.publicPlayerInfo` 与 `PlayerInfoView` 共享玩家单路径段校验，拒绝路径或查询注入。
- 不修改后端接口、鉴权权限、个人主页数据或余额；不新增缓存、后台采样或交易操作。

## 验证与边界

2026-10-18 只读核实了 `/rank/coins`、`/rank/playtime` 和一份公开 `/player/info/{player}`：原始喵币榜提供累计统计，公开主页提供不同的当前余额；在线榜有同名重复行。没有发送登录、交易、上传或其他写请求。不得将这一次读取当成全量数据或持续一致性保证；逐一主页请求并非同一时刻的事务快照。

新增 14 项 XCTest 覆盖来源隔离、原始名次、名单合并、身份/别名去重、小数及并列排序、真实零值、缺失/失败/未注册、主页时长字段优先级、失败重试、迟到响应、离页与账号切换、玩家路径校验。测试使用 URLProtocol 替身，不访问真实账户。

本地为 Linux，无法运行 Xcode/XCTest；7 个改动/新增 Swift 文件通过 Tree-sitter 语法解析，`git diff --check` 通过。这些检查不能代替 iOS 编译、测试执行或真机验收。本轮推送至 main 后由现有 Actions 工作流编译并执行测试，结果须以该提交的运行记录为准。此前 2.2.2 包不含本次变更，本地未生成新 IPA。

## 设备验收

1. 两种榜单进入时默认原始来源，服务端名次与原值不变。
2. 手动切到主页模式，确认进度、指标说明及“非全服”范围提示；切回原始模式不残留主页值。
3. 快速来回切换、下拉刷新和返回上级，迟到响应不覆盖新模式，不继续发出后续主页请求。
4. 让部分主页或一份候选榜单失败，检查逐行原因/名单不完整提示；恢复网络后刷新恢复；两份榜单均失败显示错误。
5. 排名与余额使用主页字段；同额并列、0 值有效，缺失值无名次；同一账户别名不重复累计。
6. 点击玩家进入个人主页；在小屏、大字体及深浅色模式检查选择器、长名字、数值与错误可读可操作。
