# 私聊后续审查修复

日期：2026-10-22。审查基线`2400c06`，对应本机`artifacts/reviews/CHAT_FOLLOWUP_REVIEW_2026-10-21.md`。原始报告不修改，本轮版本为2.3.2；只修改iOS软件及测试，不修改、部署或审计生产Worker，不转换许可证或发布正式Release。

## 修复范围与工程选择

修复共用的解密、SQLite事务及账号范围本地写入入口，而非给每个页面添加绕过。分页、重新核验和发送接受均消费事务实际返回的过滤后记录，不能把事务前的明文副本重新塞回UI。

旧设备历史与新网络消息分开处理：不全局放宽`target_device_id`。新消息仍只接受当前设备目标；只有重新核验**加密本地数据库中的原始记录**时，才允许重解密可信旧设备历史，且必须保留原始AAD、有对应本机/归档私钥并重新核验发送钥。简单保留旧明文成本低，但不能修复旧设备重解密且可能保留未经信任的正文，因此不采用。

本人消息采用本机及已校验归档私钥对应的公钥身份。中继公钥目录或消息附带公钥不能自动成为信任来源。另一台本人设备的私钥尚未通过可信迁移/备份导入时，相关消息可能显示“无法验证或解密本人设备的消息”；本轮不靠自动信任公钥恢复可读。单独增加本人设备公钥带外核验及绑定UI是另一条扩展路径，复杂度与信任状态成本更高，本轮没有暗中加入。

## 数据兼容与边界

- `ChatMessage.validatedTargetDeviceID`是可选的本地来源标记，由成功的当前设备解密或可信本地历史迁移产生，不从relay响应字段填入。缺字段的旧SQLite记录及`nu-chat-records/1`包仍可读取，不要求SQL表迁移或清空历史。
- 旧格式已经可读且无解密错误的本地历史，只有在对应解密私钥存在时迁移目标设备来源；联系人公钥仍须独立核验。初次加载在隔离旧联系人不可靠信任之前保留此来源。只有失败网络解密的记录不能因“已落本地数据库”就获得旧设备资格。
- 重新核验失败仍移除不可信正文，不能为了维持可读而恢复从raw自动信任历史公钥的旧漏洞。先前版本已覆盖为空且没有来源标记/可信原始备份的旧记录，不据此宣称一定能恢复。
- 不可用接受只用于匹配本机原始待发与服务端接受元数据，不证明正文作者身份，也不解密隐藏内容。已删除raw且缺少匹配证据的旧孤立待发，不以猜测自动删除，仍可离线手动移除。
- 清本机历史保留Keychain私钥、已ACK游标、联系人信任及删除过滤。它不撤回服务端已接受消息、不删除另一端内容、不重新同步已ACK旧页。前台监控通过既有生命周期恢复，后台不新增任务。
- 本人其他设备信任限制已明确收紧，不能把“HTTP返回本人公钥集合”当作带外认证。真实双设备恢复/迁移仍需验收，不宣称本轮已完成真实跨端联调。
