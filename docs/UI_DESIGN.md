# StarWave iOS 界面规范

## 设计目标

StarWave 使用系统 SwiftUI 组件呈现接近原生 iOS 的体验。使用 Xcode 26 SDK 构建时，导航、标签栏、工具栏、菜单、Sheet 和标准控件自动采用 Liquid Glass。内容本身保持清晰、稳定，不以玻璃作为装饰纹理。

最低部署版本继续为 iOS 16：

- iOS 26 及以上使用系统 Liquid Glass 和标签栏滚动收起。
- iOS 16 至 iOS 25 使用系统 Material 或不透明系统分组背景。
- iOS 26 专属代码必须同时使用编译条件和运行时可用性检查。

## 信息架构

一级导航固定为五个标签：首页、社区、资源、服务、我的。每个标签维护独立的 `NavigationStack`；现有通知徽标、业务路由和数据加载行为不得因视觉改造变化。

- 首页、社区、公告、帖子和详情是内容优先页面，使用可滚动内容布局。
- 资源、下载、任务、排行榜、通知、设置及编辑流程使用原生 `List` 或 `Form`。
- 页面级操作放在 Toolbar；创建、提交、保存等动作使用标准 Button。

## Liquid Glass 使用边界

- 优先依赖系统自动提供的玻璃效果。
- 自定义玻璃只用于悬浮的功能性控件或状态浮层，不用于普通内容卡片。
- 不在一个玻璃表面中嵌套另一个玻璃效果。
- 多个需要融合或形变的玻璃控件才使用 `GlassEffectContainer`。
- 颜色只用于强调主要动作或状态，不给所有玻璃控件着色。

兼容实现集中在 `StarWave/UI/DesignSystem.swift`。业务页面不得自行复制 iOS 版本分支。

## 视觉与布局

- 使用系统背景、分组背景、系统字体、Dynamic Type 和 SF Symbols。
- 全局强调色保留应用默认 tint，不额外创建大面积品牌渐变。
- 内容卡片使用 `secondarySystemGroupedBackground`，不使用玻璃叠加。
- 不固定正文高度；长文本、富文本和图片必须能够完整滚动。
- 图像保持宽高比，加载失败时显示可识别的占位状态。
- 控件采用系统间距和至少 44×44 点的有效触控区域。
- 自定义称号从目录接口读取单字价格和最大长度；颜色选择器生成 `&#RRGGBB` 标记，预览隐藏标记并展示实际效果。费用只作本地预估，最终由服务端校验并扣除。

## 动效与无障碍

- 动效以系统导航转场、Sheet、按钮反馈和 iOS 26 标签栏收起为主。
- 不添加持续运行的高光、粒子或大面积 GPU 玻璃动画。
- 必须验证浅色、深色、增强对比度、降低透明度和减弱动态效果。
- 纯图标按钮必须提供明确的 `accessibilityLabel`。
- 空状态按一个语义元素朗读；文本支持大字体和多行显示。

## 验收清单

- iOS 26 导航功能层呈现原生 Liquid Glass，内容层没有玻璃堆叠。
- iOS 16 至 iOS 25 能启动、导航并显示材质降级效果。
- 五个标签、通知徽标、刷新、发帖、图片、点赞、下载、任务、排行榜、称号和设置行为保持可用。
- 小屏、大字体、浅色、深色和无障碍显示设置下均可滚动、点击并阅读。

## 构建缓存

CI 按 Xcode 主版本隔离缓存 Homebrew/XcodeGen 下载、SwiftPM 缓存和 Xcode DerivedData。DerivedData 的主键包含工程与全部 Swift 源码哈希，并使用同 Xcode 版本的恢复前缀加速增量编译；IPA、签名数据、用户数据和模拟器设备状态不进入缓存。

开发者功能默认隐藏，通过设置页版本号连续点按 7 次启用。入口使用原生 List/Form，按接口调试、运行状态和本地数据分组；自定义 HTTP 与令牌外发必须以醒目的风险提示展示，写请求需要确认。性能页默认仅在打开时每 2 秒采样；“持续采样”开启后才在 App 运行期间持续记录。
