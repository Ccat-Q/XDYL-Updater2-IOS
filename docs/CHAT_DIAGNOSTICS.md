# iOS 聊天连接与加密诊断

入口：私聊设置中的“连接与加密诊断”，或设置页右上角“诊断”。这是独立页面；离线或尚未启用聊天时也能进入，不会因为打开页面而连接、登记设备、生成密钥或上传日志。

## 保存范围与隐私

- 默认开始记录，仅保存在**当前 App 进程内存**；最多 400 条、最长 24 小时，最早条目自动裁剪，近邻重复事件合并计数。结束进程后不保留。
- 切换账号、切换中继或停用聊天会清除相关记录和快照；旧网络请求的迟到回调不能写入新账号记录。前后台暂停保留当前日志，但使旧回调失效。
- 暂停记录不影响实际聊天。清空仅清除事件；当前快照及记录开关保留。详情按事件 UUID 实时查找，记录被清空或裁剪后，已打开的旧详情也会失效。
- 不记录消息正文、密文、nonce、请求/响应 body、Authorization、原始 URL/query、私钥、会话密钥、恢复码或任意服务端错误文本。
- 标识只显示截断 SHA-256 引用；公钥只显示 DER SPKI 的 SHA-256/16。它们是排查元数据，不是聊天会话密钥指纹，也不是绕过原有指纹核验或重新信任的依据。

## 页面信息

- App 版本、构建号、Git 源码 revision 和系统版本；Actions 为所有构建注入同一提交的 `ChatSourceRevision`。未知值明确显示“未知”，不拿 marketing version 相同当作构建相同。
- 当前连接状态、会话是否存在、中继和设备引用、活动/历史密钥数量、待核对轮换状态。
- 本机公钥指纹与本地公私钥配对校验（匹配/不匹配/无法验证）。仅本地从私钥推导公钥后比较，不显示私钥，不上传校验输入。
- 连接分阶段：V2 能力、主站身份、会话交换、设备公钥核对；HTTP 只记录请求类别、状态、耗时，不能从日志取得完整请求。
- 同步区分获取、提交及 ACK，不把收到 HTTP 200 当作消息解密或已读成功。
- 加解密区分信封、目标设备、本机钥、对端信任、ECDH、HKDF、AES-GCM 和明文格式校验，分别记录开始/成功/失败。追踪同步且只传枚举，不改变原有密码参数或原始底层错误。

“刷新快照”只读取已有本机状态，不修复、不换钥、不刷新联系人公钥，也不触发网络。

## 失败阶段码

| 阶段码 | 含义 |
| --- | --- |
| `SCHEMA_UNSUPPORTED` | 信封字段或协议不受支持 |
| `TARGET_MISMATCH` | 信封目标与当前设备不符 |
| `OWN_KEY_MISSING` / `OWN_KEY_INVALID` | 本机缺少指定钥，或无法导入 |
| `OWN_KEY_PAIR_MISMATCH` | 本机保存的公开部分与私钥推导结果不一致 |
| `ALGORITHM_MISMATCH` | 信封算法与 key ID 所指本机钥的算法不一致；不尝试跨曲线解密 |
| `PEER_UNTRUSTED` / `OWN_SENDER_UNVERIFIED` | 对端或本人历史发送公钥尚未通过既有安全校验 |
| `CIPHER_FORMAT_INVALID` | Base64、nonce、分隔或密文封装格式无效 |
| `PEER_KEY_INVALID` / `KEY_AGREEMENT_FAILED` | 对端公钥导入或 ECDH 失败 |
| `AEAD_AUTH_FAILED` | 仅在实际 AES-GCM 认证失败时记录，不用它统称缺钥或格式问题 |
| `PLAINTEXT_INVALID` / `CRYPTO_FAILED` | 解密后格式无效，或其他未细分密码操作错误 |

阶段码不自动证明攻击或某一端故障，也不能让服务器恢复缺失私钥的历史。先对应实际构建、协议、曲线、本机配对与公钥引用排查，不清空应用数据或自动覆盖旧身份。

## 复制与排查

支持分类和仅失败筛选、单条详情复制、复制全部以及确认清空。全部导出不受当前筛选影响，页面会明确提示。复制只发生在用户点按后，写入本机剪贴板并设置 5 分钟过期及 localOnly，不自动同步 iCloud 或提交服务端。导出仍含时间和操作元数据，请只发给可信维护者。

诊断页与解密失败卡能帮助区分[生产曲线回归](CHAT_SERVER_SYNC_2026-11-15.md)和既有的本地缺钥/信任/缓存问题，但实际手机的根因仍须安装相应诊断构建并取得阶段码。CI 的合成测试不是实际手机解密成功证明。

## 验证边界

新增测试覆盖模型限额/TTL/暂停/导出白名单/账号隔离/迟到回调，HTTP 状态与失败阶段，双曲线 V1/V2 trace 与无 trace 字节一致、篡改、非法格式、配对校验，以及诊断 UI 的筛选、UTC 时间、旧详情失效、剪贴板参数和浅深色附件。

所有 iOS 编译和 XCTest 都由[并行 Actions](IOS_CI.md)执行；本机仅进行源码、YAML、plist 和不打包的 Node 单元检查。诊断功能未在生产开启新增日志，也不会让 App 自动上报；服务端共同曲线修复后来另经用户授权部署，未执行数据库写入或迁移。
