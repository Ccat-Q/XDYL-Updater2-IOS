# iOS 私聊 V2 路由、核验与密钥轮换

2026-11-15 初次实现根据用户提供的 `NU_CHAT_DESIGN.md` 调整客户端，当时不修改或部署 Worker，不将 V1 改成 iOS 原生协议。同日后续按用户要求新增[诊断页](CHAT_DIAGNOSTICS.md)，并[同步实际生产源码及获授权部署兼容修复](CHAT_SERVER_SYNC_2026-11-15.md)；当前状态以这些后续记录为准。

## 协议与路由

- iOS 继续使用 `nu-chat-v2`，能力核验失败不降级交换会话或发送消息。
- 内置中继 `https://nu-pe-chat.cc.cd` 使用 `/iOS/chat/v2/...`；自定义 HTTPS 中继默认保持 `/chat/v2/...`。`ChatRelayRoute` 支持显式选择根路由或 iOS 挂载，但不竞速或重试携带凭据的端点。
- V1 明确标为“旧协议 · 安卓兼容”；兼容消息仍经 V2 的 legacy 适配接口处理。自动模式保留优先 V2 的既有行为，显式旧协议模式仍需服务端能力和兼容主设备授权。
- `ChatValidation.relay` 继续仅接受 HTTPS origin，不把 `/iOS` 写入账号、信任记录、Keychain 或本地数据库命名空间；已有自定义中继设置不变。
- 附件说明的生产网关会剥离 `/iOS` 前缀。初次实现时仓库仅有根 `/chat` 的旧快照；同日后续已从真实生产 Source Map 恢复前缀处理和原始模块，并在授权部署后验证两个入口、代码哈希及 11 个模块源哈希一致，详见[生产同步与部署记录](CHAT_SERVER_SYNC_2026-11-15.md)。

## 连接核验

匿名中继能力请求与主站资料刷新并行执行，能力请求单独使用 5 秒请求超时；这不是完整连接的总耗时保证。能力、稳定账号身份及生命周期全部核对通过后，才能向已配置中继的准确会话接口发送主站凭据。

继续复用既有单次连接任务，避免并发调用重复交换会话。保持禁止重定向、响应 origin/path 校验、独立临时 URLSession 和会话接口主凭据白名单，不增加认证端点回退或自动协议降级。

## 本机 V2 密钥轮换

入口：私聊设置 → 聊天设备 → 密钥轮换（V2）。用户确认后：

1. 在本地写锁内核验当前设备、已登记版本及服务端旧协议绑定状态。
2. 生成新一组 X25519/P256 密钥，将候选私钥与 `expectedRevision` 先写入 Keychain 的可选 `pendingRotation`，保留现有活动密钥。
3. 使用原设备 ID 和 `expected_revision` CAS 发布候选。服务端成功响应可能是历史幂等结果，因此发布后再次读取本人公钥集合，确认设备、版本和全部候选公钥一致，才完成本地切换。
4. 将旧活动密钥归档，保留原设备 ID、本地数据库密钥和聊天历史；不改写待发消息的 UUID、nonce 或原始密文。
5. 发布结果不确定、网络失败或最终 Keychain 保存失败时，不丢弃候选。重新连接会读取最新钥环并核对云端：候选已生效则完成归档，仍为原钥则重放完全相同的 CAS，其他冲突则拒绝覆盖。

连接恢复、轮换、旧协议主设备设置、新设备创建及历史导入使用同一本地写锁；连接在锁内发布已核对的钥环，避免旧会话快照覆盖新状态。已开始发布的轮换在成功或失败后均使旧连接失效，避免后续操作继续使用旧钥环。

### 限制与安全说明

- **旧协议 V1 兼容主设备暂不支持轮换**，即使其 legacy 绑定已停用，也不自动覆盖原有兼容身份。旧安卓缓存公钥及绑定仍需单独设计迁移流程，不能当作一次普通 V2 轮换处理。
- 无法核验旧协议绑定时安全拒绝操作；未完成轮换核对前，不能再次生成候选、创建新设备或启用旧协议兼容。
- 轮换改变设备集合指纹，联系人需要重新核对并信任。保留旧私钥用于历史解密不等于前向保密；已无法解密且没有对应旧私钥的历史不会凭空恢复。
- 建议轮换前保存备份，轮换完成后重新制作备份。旧备份不包含后来生成的新密钥。
- 已被服务端接受的待发消息按原请求幂等重试；从未接受且版本已经过期的请求仍遵循既有密钥变化错误处理，不自动重新加密发送。

## 历史备份与恢复

历史消息、联系人和最新 Keychain 钥环在同一临界区取得快照，避免并发导入后“有消息、缺归档解密钥”的备份。候选状态未完成核对时拒绝打包，避免导出旧连接钥环。

历史恢复锁内的过滤器复核及迁移确认，以及备份快照内的过滤器读取，使用捕获连接直接发送，不递归调用 `connect()`；会话过期正常失败，不因续期再等同一把锁而死锁。
